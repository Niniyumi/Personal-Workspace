# 课程录音转笔记测试用例

## 自动化覆盖

- 登录用户创建课程，标题会去除首尾空格并进入 `RECORDING`。
- 课程、详情和笔记修改始终按当前用户隔离。
- 相同分片重复上传不重复写文件；完成前校验分片编号连续且总时长不超过 90 分钟。
- 完成录音后进入 `PROCESSING`；逐片转写并按顺序拼接，转写成功后立即保存原文并进入 `TRANSCRIBED`。
- 转写完成后不自动生成笔记；用户点击“生成笔记”才调用模型，成功后保存 Markdown 笔记并进入 `READY`。
- 原始音频、完整转写和整理后的笔记同时保留；转写或生成笔记失败时仍保留已经成功的内容。
- 音频列表与读取接口按当前用户隔离，前端支持回听原始录音。
- 前端 multipart 字段、最终分片先上传再完成、麦克风拒绝、受保护路由、列表、回听和详情编辑均有测试。

## 本地冒烟测试

1. 配置 `DASHSCOPE_API_KEY`，启动 MySQL、后端和前端。
2. 登录后进入“课程笔记”，输入课程名并允许麦克风权限。
3. 录制 10—20 秒后结束录音，等待状态变为“已转写”，检查完整转写内容。
4. 在课程详情回听原始录音，确认录音没有因为转写成功而被删除。
5. 点击“生成笔记”，等待状态变为“已完成”，检查整理后的 Markdown 笔记。
6. 修改笔记并保存，刷新页面确认录音、转写和笔记都仍然存在。

真实语音接口需要网络和有效密钥，因此只作为手工冒烟测试，不伪装成自动化通过。
