# 最长 150 分钟 M4A 上传、转写与课程笔记设计

## 目标与边界

用户可以在现有“课程笔记”页面上传一份已有的 M4A 录音（最多 150 分钟、512 MiB），先可靠保存原始录音，再由系统自动转写，最后由用户主动点击“生成笔记”。原始音频、完整转写、整理后的笔记均可在课程详情查看。原有浏览器录音流程继续保留 90 分钟上限，不因文件导入而改变。

本项目使用人数少，优先单机可运行和可定位失败：不引入 OSS、消息队列、分布式任务平台、说话人分离或批量多文件上传。暂只支持 M4A；其他格式不是本期验收范围。不能保证损坏或特殊编码的 M4A 被正确解码，必须根据实际解码结果提示错误。

## 依据与方案选择

现有 `QwenSpeechProvider` 将完整文件读入内存并 Base64 发送，固定声明 `audio/webm`；所用 `qwen3-asr-flash` 官方限制单次最多 5 分钟、10 MB，不能直接接收 150 分钟 M4A。[阿里云语音模型规格](https://help.aliyun.com/zh/model-studio/asr-model)

备选方案是 `qwen3-asr-flash-filetrans` 长音频模型；它支持 M4A、2 GB/12 小时，但要求可访问的文件 URL 和异步任务。使用它需要云端文件上传或可公网访问的存储、任务查询和相关配置。虽然单次模型调用更直接，但对当前项目增加了外部存储和运维面。[阿里云非实时语音识别指南](https://help.aliyun.com/zh/model-studio/non-realtime-speech-recognition-user-guide)

本期选择**本机 FFmpeg/ffprobe 切段，复用现有短音频 ASR**。实施时仅安装 FFmpeg 这一项必要工具，明确配置可执行文件路径；不依赖用户手工预先切音频。服务端从不把完整 512 MiB 文件作为 `byte[]` 或 Base64 装入内存。

## 用户流程

1. 课程页面保留“开始录音”，另加“上传 M4A”入口；录入课程名称并选单个 M4A。前端立即检查扩展名、大小不超过 512 MiB，并显示上传进度。
2. 后端创建归属当前用户的课程导入记录，并保存预期文件大小。浏览器以 8 MiB 左右的块顺序上传；失败时显示原因并允许重试当前块。上传状态接口返回服务器已保存的字节偏移，刷新页面后可选择同一文件继续，而不是无条件重传。
3. 服务端在项目数据目录按服务端生成的课程 ID 保存 `.upload` 临时文件；每块按预期偏移追加，拒绝超出 512 MiB、越序或非本人请求。接收完毕后用 ffprobe 验证文件实际格式、时长在 1–9000 秒内。通过后原子改名并持久化原始 M4A 路径；转写失败也不删除原音频。
4. 后台 FFmpeg 把 M4A 转成单声道、约 32 kbps 的 WebM/Opus，按 270 秒切段。逐段验证不超过百炼 5 分钟/10 MB 限制；单段超限或 FFmpeg 非零退出时停止并显示明确错误。
5. 沿用现有 `qwen3-asr-flash` 顺序转写 WebM 段。每段完成后保存该段文字和处理进度；重试只处理尚无转写的段。全部完成后按段号拼接完整原文并将课程置为 `TRANSCRIBED`。
6. 用户在详情页检查原文并点击“生成笔记”，沿用现有 `qwen-plus` 笔记功能。生成失败不清空已保存的原文或音频；可再次点击重试。原文较长但仍由现有模型处理，若模型返回输入过长错误，应保留原文并清楚反馈，不在首版增加多轮摘要链。

## API 与数据

- 新增仅针对已登录用户的上传创建、查询偏移、追加数据块、完成上传四个接口。创建返回课程 ID；追加接口使用二进制请求体和显式偏移，服务端独立限制每块不超过 8 MiB，不依赖 multipart 限制。完成接口只在已接收字节数与预期大小一致、ffprobe 校验成功后启动异步处理。
- 新增原始 M4A 的鉴权读取接口，使用流式/Range 响应，避免为两小时半文件调用现有 `byte[]` 回放方法。前端用 `<audio controls>` 播放，用户不必加载全部音频到内存。
- 一条 Flyway 增量迁移：将 `courses` 时长 CHECK 从 5400 秒提高到 9000 秒；增加区分浏览器录音/文件导入的来源标记及原始音频路径；为 `course_audio_parts` 增加每段转写文本列。原有数据保持原样。课程上传中使用明确状态，避免在历史列表误标“录音中”。
- 浏览器录音仍最多 18 段/90 分钟；M4A 导入按 270 秒切段，最多约 34 段，采用独立的导入校验，不直接放宽现有录音接口。
- 原文件、片段和数据库记录按 `userId/courseId` 对应；所有路径由服务端生成，不信任上传文件名或客户端路径。

## 状态、失败与日志

- 状态顺序：`UPLOADING → PROCESSING → TRANSCRIBED → PROCESSING → READY`。单块传输失败仍停在 `UPLOADING`，可从已保存偏移继续；文件校验或转写失败才进入 `FAILED`，已保存的有效原文件及已转写段保留。详情页提供“继续转写”或“重新生成笔记”。
- 上传进度按已保存字节数计算；转写进度按已完成片段数计算。浏览器关闭不影响已完成上传后的后台转写。应用重启后若任务停在 `PROCESSING`，用户可手动继续；首版不增加任务调度器自动恢复。
- 统一 `/api` 请求日志继续工作；另记录上传块序号、字节数、课程 ID、音频总时长、切段数、转写完成段数和失败阶段。控制台及文件均可按 traceId/课程 ID 查找，不记录原始文件名、音频、转写正文、笔记、密钥。
- FFmpeg 不存在、格式无效、超过大小/时长、磁盘写入失败、百炼失败都给出能理解的前端提示。失败时不误报成功，也不悄悄清空用户数据。

## 验收与非目标

自动化验证覆盖：上传偏移和块重试、非本人访问、512 MiB/9000 秒边界、FFmpeg 失败、分段顺序及大小、断点转写、原音频 Range 回放、手动生成笔记、现有浏览器录音回归。自动化测试不调用真实百炼，不要求提交用户录音样本。

人工验收先使用一份短 M4A，再由用户用一份接近 150 分钟的真实文件检查完整上传、原音频播放、转写质量、转写进度和费用。费用取决于实际百炼调用量，首版不承诺免费额度足够；长音频大约会产生 34 次短音频 ASR 请求和一次笔记模型请求。

不在本期提供 M4A 之外的格式、多文件批量导入、说话人识别、音频在线编辑、自动删除旧录音、跨机迁移或自动摘要流水线。
