# 登录功能测试用例

## 自动化测试

在 `frontend` 目录执行：

```powershell
npm run test -- --run
npm run build
```

测试覆盖以下边界：

| 编号 | 场景 | 预期结果 |
|---|---|---|
| A01 | 保存、读取和清理令牌 | 令牌数据保持一致，损坏数据自动移除 |
| A02 | 注册、登录、当前用户、刷新、退出 API | 请求路径、方法、载荷和 Authorization 正确 |
| A03 | 用户名或邮箱登录 | 保存令牌并取得当前用户，状态变为已登录 |
| A04 | 登录失败 | 清理旧会话并显示稳定的中文错误提示 |
| A05 | 页面启动时存在有效令牌 | 恢复当前用户，不调用刷新接口 |
| A06 | Access Token 失效 | 只刷新一次，再获取当前用户 |
| A07 | 刷新失败 | 清除本地令牌并回到未登录状态 |
| A08 | 服务端退出请求失败 | 本地仍退出，不让页面卡在登录态 |
| A09 | 未登录访问工作台 | 跳转到登录页并保留原目标地址 |
| A10 | 已登录访问登录或注册页 | 跳回个人工作台 |
| A11 | 登录、注册表单提交 | 调用对应 Store 方法并跳转到正确页面 |
| A12 | 工作台退出 | 清理会话并跳转登录页 |

## 浏览器联调用例

先启动 MySQL、Spring Boot 后端和 Vite 前端，再按顺序检查：

| 编号 | 操作 | 预期结果 |
|---|---|---|
| B01 | 未登录打开 `/` | 自动进入 `/login?redirect=/` |
| B02 | 提交合法注册信息 | 进入登录页并显示“账号创建成功” |
| B03 | 使用错误密码登录 | 留在登录页并显示中文错误，不泄露后端细节 |
| B04 | 使用正确密码登录 | 进入个人工作台，显示用户名称和邮箱 |
| B05 | 已登录时刷新网页 | 仍停留在工作台，不需要再次输入密码 |
| B06 | 点击退出登录 | 返回登录页，重新访问 `/` 仍被拦截 |
| B07 | 375px 左右窄屏查看登录和工作台 | 表单单列显示，无横向滚动，主要按钮可点击 |

测试账号只用于本地数据库，不写入源码、文档或 Git 历史。
